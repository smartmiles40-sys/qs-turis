# Sprint 2026-07-27 — Atendimento de WhatsApp nativo no QS

**O pedido do Bruno:** "cada SDR só ter os leads que estão na cadência dele, assim não ficando uma confusão de leads".

---

## 1. Por que não deu pra resolver no Chatwoot

Checado na instância de produção em 2026-07-27:

```
GET https://chat.setuforeuvouviagens.com.br/api/v1/accounts/1/custom_roles  →  404
```

"Papéis personalizados" — o único jeito nativo de prender um agente às conversas
dele — é recurso **Enterprise**. Na community que rodamos, **todo agente membro de
uma caixa enxerga a caixa inteira**. A aba "Minhas" é filtro de tela, não permissão.

O QS, ao contrário, já separa por dono **no banco** desde `0007_rls_papeis.sql`:

```sql
using (qs_is_manager() or owner_id = auth.uid() or owner_id is null)
```

Daí a decisão: **trazer a conversa pra dentro do QS** e deixar a RLS do lead mandar.

## 2. Como ficou

```
WhatsApp ──▶ Evolution ──▶ Chatwoot ──webhook──▶ /api/wa-webhook ──▶ Supabase
                                                                        │ RLS pelo dono do lead
                                                          SDR no QS ◀───┘  (realtime)

SDR escreve ──▶ /api/wa-send ──(confere o dono ANTES)──▶ Chatwoot ──▶ WhatsApp
```

O Chatwoot continua sendo o motor. O que mudou é **quem mostra** a conversa.

## 4. O que isso resolve de quebra

Some a necessidade de o SDR ter conta no Chatwoot — e com ela caem 3 pendências antigas:
o **SMTP** para convites, a **senha/confirmação dos 3 SDRs** no super_admin, e a
dependência de o SDR acessar o QS por `qs.setuforeuvouviagens.com.br` para o cookie
do iframe grudar (incluindo o problema do service worker com cache velho).

## 5. Limites conhecidos (honestidade)

- **Anexo, áudio e imagem aparecem como link** para abrir, não embutidos na bolha.
  Enviar anexo pelo QS **não está implementado** — só texto.
- **Respostas prontas (canned responses)** do Chatwoot não foram portadas.
- **Lead sem telefone no QS, ou telefone que não bate**, não casa com a conversa: ela
  fica só no Chatwoot. O casamento ignora o 9º dígito e o +55, mas não adivinha número
  errado.
- **Quem não é lead** (fornecedor, curioso) continua só no Chatwoot — de propósito.
- O gestor/admin vê todas as conversas, como já vê todos os leads.
- A migration **não foi aplicada por mim**: o MCP do Supabase desta máquina só tem o
  projeto do Dashboard conectado, não o do QS. Por isso o passo 1 é seu.

## 6. Decisão pendente (não bloqueia)

fica mais fácil, porque a divisão que importa (carteira do SDR) passou a ser do QS.
